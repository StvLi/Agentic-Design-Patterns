# 第 9 章 · Learning and Adaptation

书里这一章几乎没有可跑的代码：**14 行构造 + 三个占位路径**，而且 API 已经变了。
真正有价值的是它的全景分类，以及 `OpenEvolve` 这个"进化式代码优化"的具体做法。

## 一句话

> 让 agent 通过学习改变自己的**思考、行动或知识**。本章给分类，最后落到一种能自动跑的
> 形态：把代码当基因、把评估器当自然选择。

## 本章骨架：六类学习方式

| 方式 | 靠什么改进 | 书里的例子 |
|---|---|---|
| 强化学习 | 奖励 / 惩罚 | 机器人控制、游戏 |
| 监督学习 | 标注样本 | 邮件分类、趋势预测 |
| 无监督学习 | 无标注数据里的模式 | 探索性数据分析 |
| Few-shot / Zero-shot | 大模型既有能力 + 少量示例 | 快速适应新指令 |
| 在线学习 | 持续到来的新数据 | 实时反应 |
| 基于记忆的学习 | 回忆过去经验 | 与第 8 章衔接 |

两个具体算法：

- **PPO**：核心是"裁剪"——把每次策略更新限制在信任域内，防止一步走太远导致崩溃
- **DPO**：直接优化人类偏好，跳过"训练奖励模型 + PPO"两步，更简单

两种自我改进系统：

- **SICA**（Self-Improving Coding Agent）：agent 改写自己的代码
- **AlphaEvolve / OpenEvolve**：LLM 生成候选程序 → 自动评估 → 选择 → 再变异，进化**整个代码文件**

## 书里那段代码为什么跑不了

```python
evolve = OpenEvolve(
    initial_program_path="path/to/initial_program.py",   # 占位
    evaluation_file="path/to/evaluator.py",              # 占位
    config_path="path/to/config.yaml"                    # 占位，且 0.4.1 不接受这个参数
)
best_program = await evolve.run(iterations=1000)
```

三个路径全是占位符；`config_path=` 在 0.4.1 里已经改成要传 `Config` 对象
（`load_config(...)` 的返回值）。1000 轮在本机也不现实。

## 可运行实现

目录：`ch09_adaptation/`（在仓库外，与 ch01–ch07 同级）

| 文件 | 作用 |
|---|---|
| `initial_program.py` | 待优化程序：三重循环的最大子段和，只有 `EVOLVE-BLOCK` 之间会被改写 |
| `evaluator.py` | `evaluate(program_path) -> dict`，`combined_score = 0.7×正确性 + 0.3×速度` |
| `configs/` | 五个后端各一份配置，文件名 = 模型标识 |
| `local_openai_shim.py` | 把 Ollama 原生 `/api/chat` 的 `think:false` 包成 OpenAI 协议 |
| `run_sweep.sh` | 一次跑完五个后端，各 20 轮 |
| `summarize.py` | 解析 `runs/*/logs`，输出逐轮得分表 |

评估器的契约很窄，但这是整章的地基：**必须有一个能自动执行、可重复、可比较的打分函数**。
没有它，进化无从谈起。

三个特征：**非单调**（第 1 轮就比基线差）、**有崩溃**（18%）、**会收敛**（第 8 轮到达上限，

### 三个发现

**① 门槛在 0.8B 与 2B 之间，而且是断崖**

0.8B：8 轮、18% 崩溃、最终只做到 **O(n²)**。
2B：一轮写出标准 Kadane，零崩溃。
中间没有过渡带。

**② "改写代码"的门槛远低于"批判代码"**

第 4 章实测：0.8B 与 4B 都当不了合格批判者，9B 也只跨了一半。
本章：**2B 就能一次写出正确的 O(n) 算法**。

同一批模型，两种任务的门槛差了 2–4 倍。这也解释了为什么第 4 章的反思循环在弱模型上
完全失效——它连"生成"这一半都勉强。

**③ 评估器的形状决定进化会找到什么**

2B / 4B / 9B / DeepSeek 都拿到 1.000，但代码质量差一个量级：

| 模型 | 最终解 | 200 元素耗时 |
|---|---|---|
| 0.8B | O(n²) 两层循环 | 0.6 ms |
| 2B / 4B / 9B | O(n) Kadane | 20–30 µs |

评估器的速度阈值是 2 ms，O(n²) 恰好压在下面，所以**满分不代表最优**。
如果把计时的数组从 200 加到 2000，O(n²) 必然超时，进化才会被迫继续找 O(n)。

## 单文件，还是多文件项目

`controller.py:271` 读初始程序的方式是 `open(path).read()`——**一个字符串**。
提示里送的也只是这份代码。所以：

| 形态 | 支持 |
|---|---|
| 一个文件里多函数 / 多类 | ✅ 书里"evolve entire code files"就是这个 |
| 多文件互相 import 的项目 | ❌ 不原生支持 |

四条现实路径：

1. **合并成一个文件**：把依赖内联。注意 `max_code_length` 默认 10000 字符。
2. **入口文件 + 固定依赖**：被进化文件 `import` 不变的模块。能跑，但模型**看不到依赖源码**，
   只能盲调。
3. **自写外层循环**：绕开"单文件"假设，自己做 `生成 patch → 应用到工作树 → 跑测试 → 打分`。
   SICA 与 SWE-bench 类 agent 走的就是这条。
4. **分层进化**：外层进化架构、内层逐模块跑 OpenEvolve。评估要能分层给分，复杂度高一档。

为什么它刻意只做单文件：多文件一进来，评估就退化成"跑整个集成测试套件"，
成本与噪声都上去，而**廉价可靠的打分**正是这套方法的前提。

## 持续更新进化：部分支持

| 能力 | 情况 |
|---|---|
| 断点续跑 | ✅ `--checkpoint` + `checkpoint_interval`（默认每 100 代） |
| 种群跨 run 保留 | ✅ 需显式设 `database.db_path`（默认 `in_memory: true`） |
| 在线 / 持续学习 | ❌ 没有，`run()` 是离线批处理，跑完即退 |

要"持续"，得自己加调度：用同一个数据库反复续跑，评估样本可以更新。
**进化是批次的，持续性是调度器串起来的**，不是算法内置。

## 坑

1. **思考型模型：`/v1` 关不掉思考**
   Qwen3.5 默认把 token 花在 `reasoning` 上，`content` 返回空串。`think: false` 只在
   Ollama **原生** `/api/chat` 生效，`/v1` 会忽略（实测）。故加了 `local_openai_shim.py`。

2. **小参数模型写不好 SEARCH/REPLACE 补丁**
   本地配置全部设 `diff_based_evolution: false` 让它整文件重写；DeepSeek 保持补丁式。
   顺带一提：DeepSeek 20 轮里也出现过一次 `No valid diffs found in response`。

3. **ollama 拉不动官方 registry**
   本机 DNS 是 fake-ip（`198.18.0.0/15`），R2 的 blob 域名解析到私有段，ollama 的 SSRF
   保护直接拒绝：`redirect target not allowed ... non-public 198.19.31.35`。
   绕法：HF 直下 GGUF → `ollama create`。

4. **notebook 里不能用 `cwd/../..` 定位**
   VS Code 常以工作区根启动内核，会推出 `/home/ch09_adaptation`，报
   `ModuleNotFoundError: No module named 'evaluator'`。改为向上逐层找含 `evaluator.py`
   的目录，并优先参考 `__vsc_ipynb_file__`。

5. **书里 API 与 0.4.1 不一致**：`config_path=` → `load_config()` 得到的 `Config` 对象。

## 与第 4 章的关系

两章都在问"agent 能不能自己变好"，但门槛不同：

| | 第 4 章 Reflection | 第 9 章 Learning & Adaptation |
|---|---|---|
| 要求的能力 | 判断质量（批判者） | 生成改进（改写者） |
| 本机门槛 | 4B 勉强能改，9B 半能判 | **2B 就能一次改对** |
| 失败形态 | 批判者说"完美"，循环空转 | 生成的代码跑不起来（18% 崩溃） |

**判断比生成本质上更难**——这可能是这两章最值钱的一条实测结论。
